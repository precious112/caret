# Caret — Decisions Log

Append-only record of design decisions. Each entry: date · decision · rationale · supersedes (if any).

> **V1 log — closed 2026-08-01.** New decisions go in the decision log at the end of
> [CARET-V2-PLAN.md](./CARET-V2-PLAN.md). Entries here remain accurate as records of what was
> decided *at the time*; several are since superseded, most notably one-way sync (reversed:
> reverse sync is Phase 9) and Caret owning its own agent (reversed: MCP, BYO agent).
> The two-layer architecture decision below still holds and is load-bearing.

For the current synthesized direction, see [CARET-V2-PLAN.md](./CARET-V2-PLAN.md).

---

- **2026-04-28 · Two-layer architecture (design layer in React + app layer in user's framework).** Rationale: page-detection across N frameworks is intractable; framework-agnostic design renderer is unrealistic; standardizing design on React unlocks richer Figma-style features. **Supersedes:** V1 thesis "design and implementation should be one layer."
- **2026-04-28 · Design layer is the first interaction layer, app layer is downstream.** Caret facilitates sync from design → app but does not enforce consistency. Trust model mirrors Figma → app today.
- **2026-04-28 · Sync is one-way (design → app) for V1.** Bidirectional deferred until usage data justifies the complexity. Implication: if a dev edits the live app directly without going through design mode, the design layer will go stale; this is accepted.
- **2026-04-28 · Design layer lives at `/.caret` in the user's repo.** Excluded from production builds; tracked by version control so the web platform can read it.
- **2026-04-28 · Token config is shared across both layers.** Enforced directly in design; indirectly enforced in app by virtue of the app implementing the design.
- **2026-04-28 · Design vs implementation as workflow modes, not just roles.** Even a solo dev hops into design mode for UI work, then back to implementation mode for sync. Two-layer separation is a workflow boundary.
- **2026-04-28 · Sync is a plan-mode workflow, not a button.** AI analyzes both layers and produces a plan covering UI + supporting business logic. Dev reviews and accepts.
- **2026-04-28 · Change tracking is git-based via `.caret/sync-state.json`.** Records last-synced commit hash. Sync flow uses `git log` for the design diff and full-state analysis of both layers for the plan. First-ever sync treats the whole design as new. Git plumbing is provider-agnostic; GitHub-specific integration lives in the web platform tier.
- **2026-04-28 · Sync acceptance is whole-plan only for V1.** Per-step acceptance deferred.
- **2026-04-28 · Design changes land on feature branches; design + sync co-located in one PR.** Main always design↔code consistent; branches are where drift is contained. Web platform abstracts git for non-devs.
- **2026-04-28 · Token schema V1 imperative set:** brand/aesthetic descriptor, color, typography, spacing, radius. Density and motion as lower-priority core. Per-component tokens deferred to V2.
- **2026-04-28 · Token wizard is hybrid (hardcoded flow + AI-assisted branching).** Reuses the existing onboarding pattern from Cline.
- **2026-04-28 · Tokens stored as JSON, split by namespace into files under `.caret/tokens/`.** Foundation always injected; component-level tokens retrievable on demand. Build-time translators emit downstream formats (Tailwind, CSS vars, Style Dictionary).
- **2026-04-28 · Wizard widget principle: pick character, auto-generate scale, allow override.** Per-token bespoke widgets (color picker + neutral character, Google Fonts picker + ratio scale, radius character slider, etc.); live component preview always visible. Custom widgets to build: color-with-auto-scale, Google-Fonts picker, live preview surface.
- **2026-04-28 · `.caret/` directory layout finalized.** Top-level: `tokens/`, `pages/`, `flows/`, `components/`, `layouts/`, `assets/`, `sync-state.json`. Pages are self-contained React components with `meta.json` sidecar. Flows live in separate `.flow.json` files referencing pages by ID.
- **2026-04-28 · Two-tier page model: pages + flows (mirrors Figma's frames + prototype mode).** A page can appear in multiple flows. Restructuring a flow is a one-file edit on the flow definition.
- **2026-04-28 · JSX navigation and flow graph are two views on overlapping info.** JSX is the runtime (`<Link>`, `router.push`, including escape hatches); flow graph is the curated narrative powering flow editor and simulation. They stay in loose sync via AI-assisted updates when the flow is restructured — not by parsing JSX.
- **2026-04-28 · States are interactive modes, not separate page artifacts.** Deviates from Figma's snapshot model. `meta.json.states` is the declared contract; pages render different modes via prop / route param / URL query / dev-tool override. Web platform exposes a state selector in the preview.
- **2026-04-28 · Caret provides the rendering shell for the design layer.** No Next.js / Remix / TanStack Router. Pages are plain React; routing derived from `.caret/pages/` directory structure by Caret's own preview/render layer.
- **2026-04-29 · Two-mode design plan: quick (default) + deep (opt-in).** Quick mode = multimodal input → direct generation → iterate visually; covers ~80% of work. Deep plan mode = multi-page system coordination, not "thinking harder per page." **Supersedes:** V1's plan-then-generate-everywhere assumption inherited from Cline plan mode. **Superseded by:** the 2026-04-29 "no distinct deep plan mode" decision below.
- **2026-04-29 · No distinct "deep plan mode" — reuse Cline's existing plan/act toggle for design context.** Act mode = quick path (default). Plan mode = considered path (valuable for multi-page work where reviewing a plan beats generate-and-revert). Multi-page consistency does not require a separate UI mode. **Supersedes:** earlier "two-mode design plan" decision.
- **2026-04-29 · Multi-page consistency comes from infrastructure + generator behavior, not a separate workflow.** Foundation tokens, shared `components/`, shared `layouts/`, vibe descriptor, flows, and a generator that **hoists shared patterns into `components/` before building pages** together cover visual / component / layout / voice / navigation / state-pattern consistency.
- **2026-04-29 · Web platform permissions: edit by default, read-only opt-in.** Two-layer architecture means `.caret/` edits can't break the app. Safety comes from git (branches, PRs, audit trail), not permissions. No granular file/directory tiers for V1. **Supersedes:** V1 spec's tiered PM/dev access model.
- **2026-04-29 · Plan mode inputs are multimodal; sketching is one option among many.** Inputs: text, references, screenshots, sketches, voice, project-page-as-template. No single input is the centerpiece. **Supersedes:** V1's tldraw-as-canvas centering of sketching.
- **2026-04-29 · Bidirectional sketching is ditched.** Reasons: AI rendering React is higher fidelity than AI sketching; bidirectional brainstorming is preserved via conversation; flow diagramming is covered by explicit `flows/*.flow.json`; tldraw licensing + protocol complexity is real cost for marginal benefit. AI's response to ambiguity is real rendered UI (1-3 variants), not sketches.
- **2026-04-29 · tldraw deferred for V1.** A minimal custom canvas (HTML5 + brush + paste-image) suffices for sketches-as-one-input. Revisit only if multi-page spatial flow diagramming becomes a V1 feature with clear payoff.
- **2026-04-29 · React confirmed for design layer. Preact eliminated.** Preact's compat layer breaks on shadcn/Radix (infinite loops, freezes, broken components — issues open 3+ years) and Framer Motion (fragile, unofficial). React 19 closed the bundle gap (~10KB vs ~7KB gzipped). Aiden Bai's editor doesn't work with Preact. Plain HTML/CSS/JS eliminated: lower ceiling for complex designs, loses component model, ecosystem libraries (shadcn, Framer Motion) not available.
- **2026-04-29 · Hybrid canvas rendering with cached screenshot thumbnails.** Only the focused page runs live React. All other pages are `<img>` tags loaded from `.caret/thumbnails/`. Screenshots captured as a byproduct of normal workflow (generation, edit-then-unfocus), never batch-rendered. Background worker re-renders stale thumbnails one at a time. Max concurrent React apps: 1 focused + potentially 1 in the off-screen renderer. No compute/memory spikes.
- **2026-04-29 · Visual editing via forked React Grab (context extraction) + three-tier editing UX.** React Grab (MIT, Aiden Bai) maps DOM elements to source file/line/component via React Fiber. Caret forks and extends it with: (1) instant inline editing for simple properties (text, color, images) — no AI round-trip, direct source write-back; (2) AI-assisted editing for complex changes via floating text/voice affordance — React Grab context piped directly into Caret's AI pipeline via plugin hooks; (3) canvas overlay as fallback for edge cases. **Supersedes:** V1 spec's "canvas overlay as default, component editor as React power mode" and earlier references to Onlook.
- **2026-04-29 · Web platform: one codebase, two deployment targets (VS Code webview + self-hosted web server).** Same features everywhere. Collaboration is git-native in both — no feature restrictions on IDE version. Cloud version deferred until traction.
- **2026-04-29 · Rendering engine: Vite dev server.** Each `.caret/pages/*/index.tsx` is a route. HMR for near-instant feedback. `.caret/thumbnails/` added to directory structure for cached screenshots.
- **2026-04-29 · Default canvas is a clean thumbnail grid; flow graph is a user-toggled overlay.** Default view has no flow arrows — clean, scannable. Flow view overlays color-coded connection arrows from `flows/*.flow.json`, with interactive edges for restructuring. React Flow (or similar) mounts as overlay only when flow view is active, not as canvas foundation. Mirrors Figma's design mode vs prototype mode split.
- **2026-04-29 · Simulation mode: run designs like an app with viewport switching.** Hides editor chrome, shows live React page with working JSX navigation between pages. Viewport presets (desktop/tablet/mobile) via iframe resize; CSS media queries respond naturally. Device frame overlay is optional, not V1-critical. Pages should be responsive by default.
